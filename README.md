# IoT 求职雷达 📡

面向**物联网工程专业大四学生(2027 届)**的实习 + 秋招信息汇总站。

纯静态、零依赖、无框架:HTML + CSS + 原生 JavaScript,任何静态托管都能直接跑。

## 功能

| 模块 | 说明 |
|------|------|
| 岗位看板 | 实习/校招岗位卡片,支持类型 × 方向 × 城市 × 学历筛选、关键词搜索、按截止/更新排序、隐藏已截止、★ 收藏(localStorage)、一键复制群聊分享文案 |
| 成都专场 | 自动汇总 `data/jobs.js` 中城市含"成都"的岗位:大厂在蓉机构(华为/腾讯/美团/京东/网易/讯飞/京东方)+ 本土企业(极米/纵横无人机/华鲲振宇/秦川物联)+ 科研院所(中电科 10/29/30 所、中移成研院),大小厂都收录 |
| 学历匹配 | 选择本科/硕士/博士,自动解析 46 条岗位的学历要求(自由文本归类:含"本"→本科、含"硕"→硕士、含"博"→博士、在校生/无学历词→不限),只展示你能投的岗位;选择存 localStorage,岗位看板学历筛选自动联动 |
| 秋招时间线 | 各公司网申→笔试→面试→Offer 节点,状态按当前日期自动计算(进行中/已结束/未开始) |
| 面经笔试 | 高频考点速查表(8 大考点 × 5-6 个知识点,手风琴展开,**每个知识点带详细描述 + 学习链接**)+ 精选面经(全部附真实原帖链接) |
| 学习路线 | 分方向技能地图,知识点可勾选,进度存 localStorage |
| 简历工坊 | **简历制作 + 优化**:在线编辑(教育/项目/实践动态增删)→ 实时 A4 预览 → 打印/另存 PDF;一键体检打分(完整性/格式/量化成果/关键词);按 6 大岗位方向(嵌入式/硬件/物联网平台/驱动/测试/算法)一键优化:补方向技能关键词、填入自我评价模板、项目按匹配度重排、生成匹配报告;可从岗位卡片一键进入对应方向 |
| 投递工作台 | 简历信息库(存本地)+ 投递清单状态跟踪(待投/已投/笔试/面试/Offer/放弃)+ 一键打开投递页 + 批量打开待投递 + 一键生成投递摘要(复制到平台求职信栏);完全离线可用 |
| 我要投稿 | **可运行投稿系统**:页内表单 → 一键生成 GitHub Issue 预填页提交(草稿自动保存);无 GitHub 账号可复制内容发维护者;板块内实时拉取展示仓库 Issues 中的最新投稿(GitHub 公开 API) |
| 反馈建议 | 反馈/建议表单(功能建议/信息纠错/Bug 反馈/其他)→ 一键生成 GitHub Issue 预填页;草稿自动保存;实时拉取展示仓库 Issues 中的最新反馈(标题以【反馈】开头) |

## 自动投递(本地脚本,半自动安全模式)

网页端无法直接操作浏览器,真正的"自动投"在仓库 `tools/auto-apply/` 目录(本地运行):

- **自动打开**各公司官网/聚合平台的投递页,**自动预填**姓名/电话/邮箱/学校等通用信息;
- **人工确认提交**:不绕过验证码、不静默提交,页面保持可见,保护账号安全;
- 自动限速(每次间隔 3~8 秒)+ 每日上限(`config.json` 的 `daily_limit`,默认 10);
- 支持官网(小米/海康/大疆/华为/汇川…)+ 聚合平台(智联/牛客/实习僧/51job…),详见 `tools/auto-apply/README.md`;
- ⚠️ 使用前请阅读风险提示:遵守平台用户协议、控制频率、账号风险自担。

## 数据说明(重要)

**本站数据由维护者人工搜集**自各公司招聘官网、高校就业网、牛客网等公开渠道,每条都标注了核实日期。**投递前请务必以各公司官方渠道为准。**

### 如何更新/新增岗位

编辑 `data/jobs.js`,按已有格式追加一条即可,字段见文件头部注释:

```js
{
  id: "company-2027",       // 唯一英文标识(成都岗位建议 cd- 前缀)
  company: "公司名",
  position: "岗位名",
  type: "校招",              // 校招 | 实习
  direction: "嵌入式软件",    // 综合 | 嵌入式软件 | 硬件 | 物联网平台 | 驱动 | 测试 | 算法
  salary: "",               // 有公开数据才填
  city: "城市A/城市B",       // 多城市用 / 分隔;含"成都"会自动进入成都专场
  degree: "招聘对象",
  deadline: "2026-10-11",   // 无固定截止填 null
  url: "官方投递链接",
  note: "要点备注",
  updated: "2026-08-29"     // 核实日期
}
```

时间线、面经、学习路线分别在 `data/timeline.js`、`data/interviews.js`、`data/roadmap.js`,格式见各自文件头注释。

> 注意:数据文件是 `.js` 而非 `.json`(赋值给 `window` 变量),这样双击 `index.html` 本地预览时不受浏览器 `file://` 跨域限制。

> **版本号维护**:`index.html` 中所有 css/js 引用带 `?v=20260830` 版本参数。GitHub Pages CDN 会缓存资源约 10 分钟,**每次更新资源文件后,把版本号 +1**(如 `?v=20260901`)再推送,所有同学强制看到新版;否则部分用户可能看到旧版(可 Ctrl+F5 强制刷新)。

### 更新上线流程

改 `data/` 下的文件 → `git add . && git commit -m "更新岗位数据" && git push` → 1–2 分钟后线上自动生效。

## 本地预览

直接双击 `index.html` 即可;或在 VS Code 里用 Live Server 打开。

## 部署(GitHub Pages)

1. 仓库 push 到 GitHub(已由维护者完成初始化)。
2. Settings → Pages → Build and deployment → Source 选 **Deploy from a branch**,Branch 选 `main` / `(root)`。
3. 1–3 分钟后访问 `https://<用户名>.github.io/iot-career-hub/`。

部署后在 `js/app.js` 里把 `SITE_CONFIG.repo` 填成 `"用户名/仓库名"`,页脚「我要投稿」按钮会自动打开 Issue 投稿模板。

## 同学投稿流程(已可运行)

1. 打开「我要投稿」板块,填写表单(草稿自动保存在浏览器,误关不丢)。
2. 点「提交投稿」→ 自动生成 GitHub Issue 预填页,登录 GitHub 后确认提交(无账号可点「复制投稿内容」发给维护者微信)。
3. 提交后投稿会实时显示在板块底部"最新网友投稿"列表(自动拉取仓库 Issues,标题以【投稿】开头)。
4. 维护者在 GitHub 上核实:信息属实 → 加入 `data/jobs.js` 上架并关闭 Issue;虚假/过时 → 关闭并备注原因。

## 六项进阶功能说明

### 1. 简历上传自动识别(简历工坊)
上传已有 PDF / Word 简历 → 浏览器本地解析(纯前端,不上传服务器)→ 自动识别姓名/电话/邮箱/学校/专业/技能并填充表单。识别基于规则匹配,**结果请人工核对**;扫描件/图片版简历无文字层无法识别,会明确提示。

### 2. 公司类型筛选
岗位看板新增「公司类型」筛选(芯片/模组/物联网平台/智能硬件/汽车电子/白电家电/互联网/通信运营商/工业自动化/安防监控/科研院所/其他,映射表在 `data/company-types.js`)+「只看知名企业」开关(上市公司/500强/专精特新/独角兽等)。成都专场、学历匹配同步支持。

### 3. 每日两次自动更新(5:00 / 12:00 北京时间)
`.github/workflows/auto-update.yml` 定时触发(cron UTC 21:00 与 04:00),运行 `scripts/auto_update.py`:校验数据完整性 → 写入真实时间戳 `data/updated.js` → 自动 commit+push。网站"最后自动更新"显示该真实时间。
**边界说明**:GitHub Actions 无法绕过平台反爬抓取岗位,当前自动更新 = 数据校验 + 真实时间戳维护;岗位内容由人工与用户投稿补充;脚本预留 `FETCH_SOURCES` 配置位,接入合规公开数据源后可实现真正自动抓取。

### 4. 平台接入与公司信用
- 每张岗位卡片「🔎 平台搜」按钮:一键打开智联 / BOSS直聘 / 牛客 / 实习僧 的公司搜索页(合规的站内搜索入口,不抓取数据)
- **招聘信息收录(合规聚合)**:商业平台禁止自动化抓取(反爬+用户协议),本站收录走"平台发现 → 投稿(选来源平台)→ 审核入库"流程,岗位卡显示「收录来源」徽章;`scripts/auto_update.py` 内置公开源尽力抓取框架(仅限公开无登录墙的源,失败跳过,绝不伪造)
- 公司信用:不存在权威的"无良公司"黑名单 API,本站采用 **正面信用标签(知名企业)+ 用户举报(反馈板块"信息纠错")+ 维护者人工审核** 机制;核验后的问题公司标注 `risky` 并全站自动隐藏(看板/成都/学历均有「隐藏问题公司」开关,默认开启;关闭开关可查看并显示「⚠ 谨慎核实」徽章)

### 5. 动态网站评估与建议
GitHub Pages 为纯静态托管(无后端/无定时任务),**无法直接做成动态网站**。本站通过 GitHub Actions 实现"准动态"(定时自动更新数据文件,刷新即见新数据)。若需真正动态化,免费升级路线(详见下文):
- **方案 A(推荐)**:Cloudflare Workers + Cron Triggers(免费支持定时任务)+ KV 存储 + Pages 托管,可做数据抓取 API、用户系统、动态渲染
- **方案 B**:Vercel / Netlify Serverless Functions(免费额度,支持 scheduled functions)
- **方案 C**:本地 Python 定时脚本 + git push(本次 Actions 已覆盖同能力)

### 6. 更新时间真实性
"最后自动更新"时间由 GitHub Actions 每次运行时用服务器真实时间(UTC→北京时间)写入,非人工手写;本地预览无 `updated.js` 时回退显示数据最新核实日期。可在仓库 Actions 页查看每次运行日志核对。

## 真正动态化(Cloudflare Workers 后端,已就绪)

`serverless/` 目录包含**完整可用的动态后端**(Cloudflare Worker 单文件 + KV 数据库 + 定时任务):

- 岗位数据存 KV,通过 REST API 实时读写(维护者可在线增删改,无需 git)
- 定时任务每天 05:00/12:00 更新真实时间戳并校验数据
- 访问统计、投稿/反馈在线存储
- 前端双模式:配置 `SITE_CONFIG.apiUrl` 后岗位从 API 实时拉取;未配置/API 故障时自动回退静态数据,网站永不空白

部署约 5 分钟(免费,无需信用卡):注册 Cloudflare → `npm i -g wrangler` → `wrangler login` → 按 `serverless/README.md` 步骤创建 KV、配置密钥、`wrangler deploy`,然后把 API 地址填到 index.html 的 `window.SITE_CONFIG.apiUrl` 并推送即可。
